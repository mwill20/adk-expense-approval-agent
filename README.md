# adk-expense-approval-agent

An expense-approval workflow built on Google's Agent Development Kit (ADK), with a
**deterministic routing gate and a human-in-the-loop approval step**.

Built during the Google 5-Day AI Agents intensive.

## The design point

The interesting part is what the LLM is *not* allowed to decide.

```
          ExpenseReport (Pydantic schema)
                    │
                    v
            route_expense          <-- plain Python comparison, no model call
             │            │
   amount < $100      amount >= $100
             │            │
             v            v
      auto_approve   review_agent  <-- RequestInput interrupt; workflow suspends
       (deterministic)              until a human answers approve / reject
```

`route_expense` is an ordinary `if` against `EXPENSE_THRESHOLD` in
`expense_agent/config.py`. Nothing probabilistic decides whether an expense needs
review. Below the threshold, `auto_approve` returns a fixed decision. At or above
it, `review_agent` yields a `RequestInput` interrupt, the workflow suspends, and
it only resumes when a human supplies `manager_decision`.

That ordering is deliberate: an LLM classifying whether an expense "seems fine"
would make the approval boundary a probabilistic one. Here the model never gates
the money decision — it assists around a control that is plain code.

`review_agent` is declared `@node(rerun_on_resume=True)` so the resumed
invocation re-enters the same node and reads `ctx.resume_inputs`.

## Layout

| Path | Purpose |
|---|---|
| `expense_agent/` | The workflow: schema, routing, auto-approval, human-review node |
| `app/` | FastAPI server, A2A adapter, telemetry |
| `tests/unit`, `tests/integration` | Unit and end-to-end server tests |
| `tests/eval/` | Eval dataset and trace generation |
| `artifacts/` | Recorded eval grade results and traces |
| `deployment/terraform/` | Single-project and CI/CD Terraform |
| `.cloudbuild/` | PR checks, staging, and production Cloud Build pipelines |

## Setup

```bash
cp .env.example .env    # then add your key; .env is gitignored
make install
```

Run and test:

```bash
make playground
```

## Notes and limitations

- `.env`, Terraform state, `*.tfvars`, and the local ADK session DB are gitignored.
  Copy `.env.example` and supply your own credentials.
- `deployment/terraform/*/vars/env.tfvars` is not committed. Create it from the
  variables in the matching `variables.tf`.
- The eval fixtures are synthetic (`alice@company.com`, and an `attacker@company.com`
  case for adversarial input). They are not real expense data.
- Recorded results in `artifacts/` are from a single local run and are not a
  benchmark.
- Much of the surrounding scaffolding was generated by `agents-cli` 0.6.1; the
  hand-written parts are `expense_agent/` and the tests. The original generated
  README is kept as `README-agents-cli.md`.
